# 04 — Features

## Recurring Events

**Why this matters:** Partiful lacks recurring event support. Organizers recreate events manually each time. Recurring events create ongoing dependency — a book club that runs 3 months on Ephemeral isn't switching back.

**How it works:**

Host creates a recurring event by setting a recurrence rule during event creation:

- Weekly (e.g., every Tuesday)
- Biweekly (e.g., every other Thursday)
- Monthly (e.g., first Saturday of each month)
- Custom interval

Each instance auto-generates with its own RSVP list, photo gallery, comments, and (if ticketed) ticket sales. The series maintains a default guest list — all guests from the series are invited to each new instance automatically.

**Guest RSVP options for recurring events:**

- "I'm always going" — auto-RSVPs Going to all future instances. When new instances are generated by the cron job, auto-RSVP is **silent** — no SMS notification. Guests find out about upcoming instances via the normal 24hr and 1hr reminder schedule.
- Per-instance RSVP — guest chooses Going/Maybe/Can't make it for each specific date

**Host controls:**

- Customize individual instances (change time, location, description for one date without affecting the series). SMS notification sent to RSVP'd guests only if date, time, or location changes — description-only edits are silent.
- Cancel individual instances without cancelling the series
- End the series (creator only, not co-hosts)
- Add/remove guests from the series default list

**Auto-generation:** New instances are generated 4 weeks in advance. This gives guests visibility into upcoming dates without creating excessive future events.

**Lifecycle:** Each instance follows the same deletion rules as a one-off event — gallery and event data auto-delete 7 days after the instance ends. The series template persists until the host ends it.

## Photo Gallery

### Upload

- Available to verified guests who RSVP'd "Going" or "Maybe" and to the host/co-hosts
- Upload via event page: tap "Add Photos" → select from camera roll or take photo
- All EXIF/GPS metadata stripped server-side on upload before storage via Cloudflare Images
- **Detailed proof shown to uploader** — not just "metadata removed" but a list of specific fields that were stripped (e.g., "Removed: GPS coordinates (40.7128, -74.0060), Camera: iPhone 15 Pro, DateTime: 2026-03-15 21:34:12, Software: iOS 19.2, 8 other fields"). This reinforces the privacy marketing claim with receipts.
- Photos stored in Cloudflare R2, encrypted at rest
- Maximum 200 photos per event gallery
- Supported formats: JPEG, PNG, HEIC (converted to JPEG on upload), WebP
- Maximum file size: 15MB per photo (resized server-side to reasonable display dimensions)

### Viewing

- Gallery visible to all verified guests who RSVP'd Going or Maybe
- Simple grid layout, tap to view full-screen, swipe to navigate
- Photos ordered chronologically by upload time
- Gallery remains active during the 7-day post-event window (guests can still view and upload)

### Download

- Any gallery viewer can download individual photos
- **Bulk zip download is a fast-follow, not MVP.** Individual download is MVP.
- Host receives SMS 1 day after event ends notifying them the gallery is available

### Deletion

- Gallery is publicly visible on event page for 7 days after event ends
- After 7 days: gallery removed from event page, individual photo URLs invalidated
- Host download link remains active until day 14
- After day 14: all photo data permanently deleted from R2. Truly gone. No encrypted backups. No recovery possible.
- This is a values decision aligned with Ephemeral's privacy philosophy

## Event Wall (Comments)

**Purpose:** Lightweight communication on the event page. NOT real-time group chat (deferred to full Ephemeral app).

**Features:**

- Host/co-hosts can post updates visible to all RSVP'd guests ("Changed the start time to 8pm!", "Bring a jacket — we'll be outside"). Host updates are visually distinguished (pinned/highlighted).
- All verified RSVP'd guests can post comments ("What should I bring?", "Running 10 min late")
- Comments are visible to all RSVP'd guests
- Comments are NOT end-to-end encrypted (server-encrypted at rest, TLS in transit)
- Comments remain active during the 7-day post-event window (guests can still read and post)
- Comments auto-delete with the event (7 days after event ends)
- No notifications for new comments (no chat notifications for web MVP)

**Why not real-time chat:** Real-time E2EE group chat is a core feature of the full Ephemeral app. Building it for the web MVP adds significant complexity (WebSocket infrastructure, key management, message storage) without proportional conversion value. The event wall covers the "what should I bring?" use case. Real-time chat is the upgrade that comes with the full app.

## Notification System

**Channel:** SMS only (via Twilio). No push notifications, no email. SMS is reliable and works for all guests regardless of device.

**Available to all verified guests** (all guests are phone-verified).

### Notification Schedule

| Trigger           | Message                                                                           | When                               |
| ----------------- | --------------------------------------------------------------------------------- | ---------------------------------- |
| RSVP confirmation | "You're going to [Event]! [date] at [time]. ephmr.al/e/[code]"                      | Immediately after RSVP             |
| 24-hour reminder  | "[Event] is tomorrow at [time]. ephmr.al/e/[code]"                                  | 24 hours before event              |
| 1-hour reminder   | "[Event] starts in 1 hour! [location]. ephmr.al/e/[code]"                           | 1 hour before event                |
| Host update       | "[Host] updated [Event]: [brief change]. ephmr.al/e/[code]"                         | When host edits event details      |
| Gallery ready     | "Photos from [Event] are ready to download. Link expires [date]. ephmr.al/e/[code]" | 1 day after event ends (host only) |

### What We Don't Send

- "You haven't responded yet!" guilt-tripping reminders
- "3 more people just RSVPed!" engagement bait
- Promotional messages for Ephemeral
- Notifications for event wall comments (no chat notifications in web MVP)
- Any notification to users who haven't RSVP'd

### Host Text Blasts

Host or co-host can send a custom SMS to all Going/Maybe guests. **Limited to 3 text blasts total per event** — this is a shared pool among the host and all co-hosts. Once 3 are sent, no more can be sent regardless of who sent them. Message format: "[Host]: [custom message] — Reply STOP to unsubscribe from [Event] texts."
